# ДЗ 2/1. Хватит ли мест?

Веб-мастерская проводит два занятия. Добавьте выбор занятия и учёт свободных мест, затем подготовьте проверенную сборку.

**База: 8 баллов. Бонусы: 2 балла.**

## Начало

Нужны Node.js 22.12+ и npm 10+. В терминале этой папки:

```bash
npm ci
npm run dev
```

Откройте адрес из терминала. Остальные команды выполняйте во втором терминале в той же папке. Live Server здесь не нужен.

**Стартовая версия:** форма и общий счётчик работают. Выбор занятия, свободные места и изображение ещё не подключены. Проверка типов проходит.

Код приложения находится в `src`, места изменений отмечены `HW-А1`–`HW-Б2`. [Справка](СПРАВКА.md) пригодится, если забыли приём из практики.

## Что должно получиться

| Занятие | Значение `workshop` | Вместимость | Исходная заявка |
| --- | --- | ---: | --- |
| TypeScript | `typescript` | 6 | Анна, 2 человека |
| Сборка проекта | `build` | 8 | Илья, 1 человек |

Одна заявка по-прежнему содержит **от 1 до 5 человек**. Все заявки занимают места независимо от статуса. Остаток считается отдельно для каждого занятия. Ровно оставшееся число мест можно занять; превышение отклоняется с объяснением, без новой записи и потери введённых значений.

После успеха форма очищается, карточка показывает название занятия, оба остатка и общий счётчик обновляются. Одинаковые имена допустимы. Данные остаются в памяти: перезагрузка возвращает две исходные заявки. Backend, хранение данных, отмена записей и новый дизайн не требуются.

Контракты функций:

- `readWorkshop(raw: FormDataEntryValue | null): WorkshopId | null`.
- `countWorkshopSeats(items: Booking[], workshop: WorkshopId): number`.
- `getRemainingSeats(items: Booking[], workshop: WorkshopId): number`.

Расчёты не меняют массив и не обращаются к DOM; `getRemainingSeats` использует `countWorkshopSeats`. Проверку нельзя заменять приведением через `as`, использованием `any`, подавлением ошибок или отключением `strict`.

### Типы и собранное приложение

1. Временно задайте `workshop: 'other'` в исходной заявке. `npm run typecheck` должен найти ошибку, а `npm run build` остановиться **до Vite**. Старый `dist` может остаться.
2. Исправьте значение, выполните `npm run build`, затем `npm run preview`. По адресу **preview** повторите сценарий, проверьте стили и изображение. Имя ресурса в `dist` может измениться, SVG может встроиться в URL.
3. Измените текст в исходнике: `preview` покажет изменение только после нового `build` и обновления страницы. Сдавайте проверенную версию.

## Бонусы: до 2 баллов

### Д1. `Result<T>`: 1 балл

Замените возврат значения или `null` у `readSeats` и `readWorkshop` общим типом `Result<T>`: успех содержит типизированное значение, ошибка содержит причину. Обработчик различает ветви по признаку, например `ok`, и показывает сообщение. Базовое поведение сохраните; изменение возвращаемых типов в этом бонусе разрешено.

**По 0,25:** общий тип применён к первой функции; применён ко второй с другим типом значения; обработчик безопасно различает результат; проверены успех и ошибка обеих функций. В проверке из базы вместо `null` ожидается ваш результат ошибки. Готовый расчёт мест и публикация для Д1 не нужны.

Для самостоятельного изучения: [Generic Types](https://www.typescriptlang.org/docs/handbook/2/generics.html#generic-types), [Discriminated unions](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions). Запросы: `TypeScript generic type alias Result T`, `TypeScript discriminated union narrowing`.

### Д2. GitHub Pages: 1 балл

Настройте GitHub Actions: установка зависимостей, сборка и публикация **`dist`** на Pages. **0,5** за воспроизводимую публикацию, **0,5** за актуальный сайт с рабочими ресурсами и реализованными сценариями. Достаточно собираемой версии, полная база и Д1 не обязательны.

Опора: [Vite: GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages). Разрешено адаптировать официальный workflow с указанием источника. Изучите `base` для пути репозитория, источник Pages и артефакт сборки: `Vite GitHub Pages base repository`, `GitHub Actions deploy Vite dist npm ci`. Проверьте имя ветки в workflow. `preview` является локальным просмотром, а не публикацией.
