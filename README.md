# ДЗ 2/1. Хватит ли мест?

Веб-мастерская проводит два занятия: «TypeScript» и «Сборка проекта». Доработайте готовое приложение записи: пользователь выбирает занятие и указывает, сколько человек придёт. Приложение принимает заявку, только если для всей группы хватает мест. Затем настройте и проверьте сборку.

**База: 8 баллов. Бонусы: 2 балла.**

## Начало

Используйте стартовый проект из этой папки, переносить код практики не нужно. Нужны Node.js 22.12+ и npm 10+. Откройте терминал в папке, где лежит `package.json`:

```bash
npm ci
npm run dev
```

Откройте адрес из терминала. Остальные команды выполняйте во втором терминале в той же папке. Live Server здесь не нужен.

**Стартовая версия:** форма и общий счётчик работают. Выбор занятия, свободные места и изображение ещё не подключены. Проверка типов проходит.

Код приложения находится в `src`. Комментарии `HW-…` указывают места доработки; номера соответствуют пунктам таблицы ниже. Изменения сборки выполняются в `package.json`. [Справка](СПРАВКА.md) пригодится, если забыли приём из практики.

## Что должно получиться

| Занятие | Значение `workshop` | Вместимость | Исходная заявка |
| --- | --- | ---: | --- |
| TypeScript | `typescript` | 6 | Анна, 2 человека |
| Сборка проекта | `build` | 8 | Илья, 1 человек |

Одна отправка формы создаёт **одну заявку на группу от 1 до 5 человек**. Поле «Имя» содержит имя того, кто записывает группу; перечислять всех участников не нужно. Например, заявка Анны занимает 2 места, хотя в списке это одна карточка.

Все заявки занимают места независимо от статуса. Остаток считается отдельно для каждого занятия: вместимость минус сумма участников его заявок. Общий счётчик показывает число участников обоих занятий, а не количество заявок. Можно занять ровно все оставшиеся места, если группа не больше 5 человек. При нехватке мест покажите объяснение: заявка не добавляется, счётчики и введённые значения не меняются.

После успешной отправки появляется карточка с названием выбранного занятия, обновляются оба остатка и общий счётчик. Форма возвращается к исходным значениям: имя пустое, занятие не выбрано, «Участников» равно `1`. Одинаковые имена допустимы. Данные остаются в памяти: перезагрузка возвращает две исходные заявки. Backend, хранение данных, отмена записей и новый дизайн не требуются.

А3 оценивает правильность расчётов, Б1 оценивает их размещение в модуле и повторное использование. Это одна реализация, писать её дважды не нужно. В Б4 оценивается проведённая проверка: если часть базы не готова, запишите, какие шаги не проходят и что происходит вместо ожидаемого результата. Ошибки поведения учитываются в соответствующих пунктах А.

Контракты функций:

- `readWorkshop(raw: FormDataEntryValue | null): WorkshopId | null`: возвращает допустимый идентификатор занятия, а для любого другого значения возвращает `null`. Сообщение пользователю показывает обработчик формы.
- `countWorkshopSeats(items: Booking[], workshop: WorkshopId): number`: суммирует число участников заявок выбранного занятия. Если таких заявок нет, возвращает `0`.
- `getRemainingSeats(items: Booking[], workshop: WorkshopId): number`: возвращает вместимость выбранного занятия минус число занятых мест.

Расчёты не меняют массив и не обращаются к DOM; `getRemainingSeats` использует `countWorkshopSeats`. Проверку нельзя заменять приведением через `as`, использованием `any`, подавлением ошибок или отключением `strict`.

## Проверка перед сдачей

### Поведение

Это проверка доработанного приложения, а не стартовой версии. Перезагрузите страницу: должны быть две исходные заявки, 4 свободных места на TypeScript, 7 на «Сборке проекта» и 3 участника всего.

Далее выполняйте строки **по порядку, без перезагрузки между ними**. В каждой строке заполните «Имя» любым непустым именем, выберите указанное «Занятие», введите число в поле «Участников» и один раз нажмите «Записаться». Например, первая строка создаёт одну заявку на четырёх человек на занятие «TypeScript».

| «Занятие» | «Участников» | Результат отправки | Свободно: TypeScript / Сборка проекта | Всего участников |
| --- | ---: | --- | --- | ---: |
| TypeScript | 4 | Добавлена одна заявка на 4 человек | 0 / 7 | 7 |
| TypeScript | 1 | Отказ: мест нет, ввод сохранён | 0 / 7 | 7 |
| Сборка проекта | 5 | Добавлена одна заявка на 5 человек | 0 / 2 | 12 |
| Сборка проекта | 3 | Отказ: осталось только 2 места, ввод сохранён | 0 / 2 | 12 |
| Сборка проекта | 2 | Добавлена одна заявка на 2 человек | 0 / 0 | 14 |

После каждого успеха проверьте название занятия в новой карточке и сброс формы. После отказа новая карточка появляться не должна. В конце перезагрузите страницу: снова две исходные заявки, свободно 4 и 7 мест, всего 3 участника.

Отдельно проверьте неверный ввод. **Перед каждой проверкой перезагружайте страницу**, чтобы свободные места были. Заполните корректно все поля, кроме проверяемого: оставьте занятие невыбранным; оставьте имя пустым; затем по очереди введите в «Участников» `0`, `2.5`, `6` и пустую строку. Каждая отправка должна показать причину отказа, сохранить значения полей, список заявок и счётчики. Ещё одной проверкой отправьте ` 2 ` (число с пробелами по краям) с именем и выбранным занятием: должна добавиться одна заявка на 2 человек.

В `src/main.ts` сразу после объявления функции `readWorkshop` временно добавьте `console.log(readWorkshop('other'), readWorkshop(null))`: откройте DevTools браузера → Console, там должны появиться два `null`. Затем удалите вызов. Расчёты можно проверять до подключения формы: для исходного массива заняты 2 места на TypeScript и 1 на «Сборке проекта», свободны 4 и 7; для пустого массива занятых мест нет, свободны 6 и 8.

### Типы и собранное приложение

1. В `src/data/initial-bookings.ts` временно замените значение поля `workshop` одной заявки на `'other'`. Запустите `npm run typecheck`, затем `npm run build`: обе команды должны сообщить об ошибке TypeScript. Вторая команда должна остановиться **до этапа сборки Vite**. Старый `dist` может остаться: это не признак успешной новой сборки.
2. Исправьте значение, выполните `npm run build`, затем `npm run preview`. По адресу **preview** повторите сценарий, проверьте стили и изображение. Имя ресурса в `dist` может измениться, SVG может встроиться в URL.
3. Измените, например, заголовок «Встречаемся на практике» в `src/main.ts`. Обновите страницу **preview** до новой сборки: там ещё старый текст. Повторите `npm run build` и обновите страницу: теперь текст должен измениться. Верните заголовок, снова соберите и проверьте приложение.

## Бонусы: до 2 баллов

### Д1. `Result<T>`: 1 балл

Замените возврат значения или `null` у `readSeats` и `readWorkshop` общим типом `Result<T>`: успех содержит проверенное значение (`number` для числа участников, `WorkshopId` для занятия), ошибка содержит строку с причиной. Обработчик различает ветви по признаку, например `ok`: при успехе использует значение, при ошибке показывает причину и не добавляет заявку. Базовое поведение сохраните; изменение возвращаемых типов в этом бонусе разрешено.

**По 0,25:** общий тип применён к `readSeats`; применён к `readWorkshop` с другим типом значения; обработчик безопасно различает результат; проверены успех и ошибка обеих функций. В проверке через `console.log` вместо двух `null` ожидаются два результата с признаком ошибки и её причиной. Д1 опирается на модель и выбор занятия: А1, А2 и включённый список из А4. Готовый расчёт мест, изображение и публикация для него не нужны.

Для самостоятельного изучения: [Generic Types](https://www.typescriptlang.org/docs/handbook/2/generics.html#generic-types), [Discriminated unions](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions). Запросы: `TypeScript generic type alias Result T`, `TypeScript discriminated union narrowing`.

### Д2. GitHub Pages: 1 балл

Настройте GitHub Actions: установка зависимостей, сборка и публикация **`dist`** на Pages. **0,5** за воспроизводимую публикацию, **0,5** за сайт, соответствующий последней сборке: стили и скрипты загружаются, а выполненные вами сценарии работают так же, как в локальном `preview`. Если выполнен Б2, проверьте и изображение. Достаточно собираемой версии, полная база и Д1 не обязательны. Workflow и настройку `base` добавьте самостоятельно.

Опора: [Vite: GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages). Разрешено адаптировать официальный workflow с указанием источника. Изучите `base` для пути репозитория, источник Pages и артефакт сборки: `Vite GitHub Pages base repository`, `GitHub Actions deploy Vite dist npm ci`. Проверьте имя ветки в workflow. `preview` является локальным просмотром, а не публикацией.
