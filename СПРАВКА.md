## Тип и проверка ввода

`interface` описывает поля объекта, `type` может дать имя набору допустимых строк. Обязательное новое поле нужно добавить и в модель, и в создаваемые объекты. После изменения модели ошибки в исходных заявках и обработчике ожидаемы: они исчезнут, когда вы согласуете эти места. `Booking[]` и `Array<Booking>` обозначают один тип массива.

Значение `FormData.get` может быть строкой, файлом или `null`. Условие сужает тип; утверждение через `as` не проверяет значение. В заготовке есть работающий пример `readSeats`: найдите переход от внешнего значения к проверенному числу. Для новой функции проверки занятия используйте тот же принцип.

Список с `disabled` не передаёт значение в `FormData`: включите его перед проверкой А2. Если удаляете стартовое уведомление, работайте с уже найденным `ui.notice` в отмеченном месте. Удаление `<aside>` из HTML-строки без изменения проверки DOM вызовет ошибку «Не найдены элементы интерфейса».

[Типы объектов и функций](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html) · [Сужение типов](https://www.typescriptlang.org/docs/handbook/2/narrowing.html).

## Модули и ресурс

`export` открывает доступ к объявлению из другого файла. Тип импортируется через `import type`, функция через обычный `import`. Готовый пример: `src/lib/count-seats.ts` и его использование в `main.ts`.

Путь в `import` считается от текущего файла. Из `lib/` путь к модели начинается с `../models/`; из `main.ts` путь к библиотеке начинается с `./lib/`, к изображению с `./assets/`. Указанные в README пути от корня проекта не нужно буквально переносить в импорты. Импорт картинки возвращает URL, который можно присвоить `src` изображения. В конфигурации уже подключён `vite/client`.

[Ресурсы Vite](https://vite.dev/guide/assets.html).

## Команды

| Команда | Что делает |
| --- | --- |
| `npm ci` | Устанавливает зависимости по lockfile |
| `npm run dev` | Запускает сервер разработки |
| `npm run typecheck` | Проверяет типы, не создавая JS |
| `npm run build` | В старте только собирает; в Б3 перед сборкой добавляется проверка типов |
| `npm run preview` | Показывает уже собранный `dist` |

Связка `команда1 && команда2` запускает вторую команду только после успеха первой. В проекте инструменты вызываются через `node node_modules/...`; это те же Vite и TypeScript. Не нужно менять эти пути.

Сервер занимает терминал до Ctrl+C. Проверку или сборку запускайте в соседнем терминале. Если npm не найден, установите Node.js и заново откройте терминал. Ошибка типов указывает файл и место: сначала прочитайте, какое значение ожидалось и какое получено.

[TypeScript в Vite](https://vite.dev/guide/features.html#typescript) · [Сборка и локальный просмотр](https://vite.dev/guide/static-deploy.html#testing-the-app-locally).
